# ハードウェア: CubeRange テストベッド

このディレクトリは実機テストベッドの設計資産を置く場所である。Renode レンジの
実機版として、STM32H753 ベースのモジュール型構成とし、第三者がここにコミット
されたものから再発注・再現できる RAMN 型のベンチを目指す。

このディレクトリのものは、まだ何も発注も製作もされていない。文書はテストベッド
ロードマップ（フェーズ1）で合意した骨格であり、KiCad ソースは `docs/testbed/` の
仕様凍結の後、フェーズ4で入る。

## 構成

| パス | 中身 |
| --- | --- |
| `lib/` | 固定したシンボルとフットプリント（ベンダ提供を優先） |
| `boards/node/` | 共通ノード基板（1設計を4枚使う） |
| `boards/backplane/` | バックプレーン: 電源配電と CAN 幹線 |
| `boards/tap/` | 着脱式の攻撃セグメント（タップ／介在ハーネス） |
| `releases/` | 実際に発注した版の製造ファイルのみ |

## システムの形

- **共通ノード基板** は1設計を4枚使う。役割（COMM、OBC、EPS、ADCS）は基板では
  なくファームウェアで切り替える。
- **バックプレーン** がノード間の電源と CAN 幹線を担う。
- 幹線の1区間は **着脱式の攻撃セグメント** とし、物理層の演習が起きる場所を
  定義され検査可能なものにする。
- 地上局は既存の Python 地上局のままとし、PC または Raspberry Pi からブリッジ
  経由で接続する。

## 設計要件

- **初期状態へ戻せること。** 演習後に全ノードを確実に初期状態へ戻せること:
  ノード別電源スイッチ、BOOT と NRST の外部制御、ノード自身のファームウェアの
  協力に依存しない再書込み経路を持つ。
- **受電は単点。** EPS の位置が USB-C 5 V を単点で受け、バックプレーンへ配電
  する。電流制限・保護・ノード別電流計測付き。v1 では電池を使わない。
- **CAN classic を実配線。** 幹線は実物の CAN classic とし、ファームウェアの
  libcsp over CAN の前提と一致させる。終端は幹線の両端のみに置き、切替可能と
  する。
- **故障は明示的な機能とする。** 終端破壊や短絡などの損傷は、明示的な故障注入
  スイッチで提供し、緩い配線や基板の損傷では行わない。
- **計測はベンチの一部。** ノード別電流計測と、電源・CAN・SWD・コンソール
  UART のテストポイントへのアクセスを備える。
- **第三者が再現できること。** KiCad ソース、BOM、製造出力をこのリポジトリで
  所有し、製造出力は CI で再生成可能にする。凍結するのは実際に発注した版のみ
  とし、`releases/` に置く。
