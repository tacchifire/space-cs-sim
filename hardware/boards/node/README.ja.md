# 共通ノード基板

1つの基板設計を4枚使う。役割（COMM、OBC、EPS、ADCS）はファームウェアで
切り替える。本プロジェクトが自前で設計する最初の基板であり、フェーズ3の
立ち上げの単位となる: 1枚、次に通信する2枚、次に4枚。

## 骨格仕様

| 項目 | 方向性 |
| --- | --- |
| MCU | STM32H753。Renode レンジが動かすのと同じ部品 |
| バスインタフェース | バックプレーン幹線への CAN classic トランシーバ |
| デバッグ | SWD ヘッダ。ノードを搭載したまま外部からアクセス可能 |
| コンソール | USB-C コンソール。ノード自身のファームウェアに依存しない |
| 電源 | バックプレーンから給電。ノード別スイッチと電流計測 |
| リセットとブート | NRST と BOOT を外部制御用に引き出す |
| 役割別 I/O | 役割別 I/O を定義したコネクタへ引き出す |

## 設計要件

- 基板は外部から既知の状態へ戻せなければならない: 電源断、NRST、BOOT 選択、
  SWD での再書込みのいずれも、動作中のファームウェアの協力なしに効くこと。
- CAN トランシーバは通常の応答（ACK）可能なモードを備えること。受信専用
  ノードは ACK を必要とする演習に参加できない。
- 電源、CANH/CANL、SWD、コンソール UART のテストポイントを備える。
- 回路図は階層シートで描き、後日の集約1枚化バリアントが再描画ではなく再利用
  で済むようにする。
