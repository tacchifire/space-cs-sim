# CubeRange のローカルWebコンソール

*English: [flatsat-web.md](flatsat-web.md)*

ローカルWebコンソールは、FlatSat の USB 接続、センサー計測、保存ログ、シミュレータの演習一覧を一つの画面で扱う。
既存の FlatSat アダプタを使い、Renode のプロセスは起動しない。

## コンソールの起動

[FlatSat の USB 診断](flatsat.ja.md) に従い、チェックアウトの外にある環境に USB 用の追加パッケージを入れる。
リポジトリのルートでコンソールを起動し、端末に表示された URL を開く。

```bash
python3 tools/flatsat.py serve
# Equivalent Make target
make flatsat-web
```

既定の URL は `http://127.0.0.1:8765/` である。
同じ Tailscale ネットワーク内の別の端末から使う場合は、このホストの Tailscale IPv4 アドレスを指定する。

```bash
python3 tools/flatsat.py serve --host "$(tailscale ip -4)"
```

tailnet のアクセス規則でこのホストへの接続を許可された端末から、表示された URL を開く。
利用者のアクセス権限は Tailscale のアクセス規則で制御し、このアドレスに到達できる端末は、記録の閲覧と画面が提供する USB 操作を実行できる。
HTTP のセッショントークンは、別オリジンからの要求を防ぐために使う。
ポートが使用中の場合は、`--port 0` で空いているポートを選ぶ。
既定の保管先は `$XDG_DATA_HOME/cuberange/flatsat/web` で、この変数が未設定の場合は `~/.local/share/cuberange/flatsat/web` を使う。
別の保管先は `--data-dir` で指定する。

```bash
python3 tools/flatsat.py serve --port 0 --data-dir "$HOME/.local/share/cuberange/flatsat-console"
```

サーバーを止めるには、起動した端末で Ctrl+C を押す。
実行中の USB 操作がある場合は、フォームで指定した時間の処理が終わってから終了する。

## スマートフォンでの利用

スマートフォンを同じ tailnet に接続し、表示された Tailscale の URL を開く。
幅の狭い画面では、メニューを画面の下端に置き、フォームを1列に並べ、保存ログを選択欄から切り替える。
グラフは画面の幅に合わせて描画し、幅の広い表は表の領域内で横にスクロールする。
セッションストレージを利用できる場合は、同じブラウザータブで再読み込みした後も、選択したログとグラフの項目を復元する。
演習コマンドを自動でコピーできない場合は、コマンドを選択したダイアログを表示するので、スマートフォンでは選択された文字を長押しして「コピー」を選ぶ。

## 基板の確認と計測

USB のシリアル番号で基板を選び、各ポートのアクセス権限の表示を確認する。
情報取得の操作は、`Cat-Shell` を通じてファームウェア、状態、センサー値を照会する。
計測フォームでは、記録時間、照会間隔、実験名、メモ、任意のしきい値を指定する。
記録時間の上限は60秒、照会間隔の下限は0.02秒である。
USB の処理は一つずつ実行し、処理中に別の開始要求を受けた場合は拒否する。

受信の操作は、無線データの送信コマンドを書き込まずにバイト列を記録する。
ポートを開けても受信が0バイトの場合は、受信データのない記録として表示し、テレメトリの受信実績とは扱わない。
ポートの権限エラーは、処理結果に表示する。
コンソールから OS のデバイス権限を付与することはできない。

## 保存ログの閲覧

記録が終了すると、保存ログの一覧に現れる。
記録を選ぶと、計測値、有効数、失敗数、グラフ、しきい値の状態変化を確認できる。
グラフは失敗したサンプルで線を切り、時刻がホストでの照会時刻であることを示す。
選んだ記録から、元の JSONL をダウンロードするか、単独で開ける HTML レポートを表示する。

以前に CLI で記録した JSONL ファイルは、アップロード欄から取り込める。
サーバーはファイルを検証してから別の記録として保存し、上限は2 MiBとする。
元のファイルを上書きせず、ブラウザーから任意のファイルパスを指定することもできない。
未完了の記録や失敗した記録は、取り込んだ後もその状態を保つ。

## 室内の変化の監視

「室内監視」を開き、基板を普段の位置に置いた状態で対象ボードを選び、監視を開始する。
既定では1時間の監視中に1秒ごとにセンサーを照会し、監視時間は最大24時間まで指定できる。
最初の有効な応答20件から、各センサー成分の中央値を使って固定した基準値を作る。
基準値の取得が終わると、変化の判定を開始する。

基板の動きは、現在の加速度 X/Y/Z と基準の加速度 X/Y/Z との差のベクトルの大きさで判定する。
加速度の合成値が約1gのままでも、基板の向きの変化を検出できる。
温度、湿度、気圧は、それぞれの開始時の基準値との差で判定する。
変化量のしきい値の初期設定は次のとおりで、画面から変更できる。

| 計測項目 | 基準からの変化量 |
| --- | --- |
| 基板の動き | 80 mg |
| 温度 | 2 °C |
| 湿度 | 10ポイント |
| 気圧 | 500 Pa |

既定では、有効な応答がしきい値以上の状態で連続3回続いたときに変化のイベントを保存する。
その後、しきい値の60%以内に連続3回収まると、回復のイベントを保存する。
欠測がある場合は連続回数を数え直し、欠測を回復とは扱わない。
基準値は監視中に更新せず、新しい監視を開始したときに取り直す。

基準値の確定、変化、回復、応答の欠測と再開を JSONL に即時保存し、60秒ごとに状態も記録する。
変化と回復のイベントには、判定に使った連続したセンサー値と USB 応答の根拠を残す。
通常時の全照会を連続計測のログとして保存することはしない。
画面では最新値とイベント履歴を確認でき、保存ログと単独の HTML レポートでは保存したイベントを確認できる。
照会の総数とイベント数は別々に表示する。

「変化インボックス」は、検証済みの室内監視ログを横断し、確認が必要な変化とセンサー取得異常だけを新しい順に表示する。
基準値の確定だけでは要確認件数を増やさない。
変化は、計測項目、検知時刻、基準との差、設定したしきい値、回復時刻を示す。
実行中の監視では継続中と表示し、終了済みの記録に回復イベントがない場合は「回復未記録」と表示する。
取得異常は環境の変化とは分けて表示する。
各項目は確認済みにした後で未確認へ戻すことができ、その状態は同じコンソールを開くスマートフォンとPCで共有される。
確認状態は別の管理ファイルへ原子的に保存し、根拠となる JSONL は変更しない。
表示する差としきい値は観察のための数値であり、危険度や安全性を判定するものではない。

「監視ログのまとめ」は、実行中の監視状態と、検証を通過した保存ログの集計を分けて表示する。
最後の保存観測は記録終了時の状態であり、現在の部屋の状態を示すものではない。
過去24時間と過去7日の件数は、ログに記録されたホスト照会時刻を基準に、変化とセンサー取得異常を数える。
集計に使う開始、観測、イベントの時刻が現在より後の保存ログは時刻確認の対象として示し、その観測とイベントは期間集計から除外する。
中断した記録を含む場合は、影響する期間ごとに集計が保存済みイベントの範囲であることを画面に示す。
中断記録の設定時間が期間内まで続く可能性を含む場合も、その期間に警告する。
最長継続は回復まで記録されたイベントだけから求め、最多項目は保存時に設定されていた基準値としきい値による検知回数である。
監視していない時間、異なる部屋や重複して取り込んだログの区別、部屋の安全性や在室状況は、この集計から判定しない。

サーバーが動いている間は、ブラウザータブを閉じても監視を続ける。
USB ポートを解放するには「監視を停止」を押し、監視が終了するまで別の USB 操作を開始できない。
応答のタイムアウトやデバイスエラーが起きた場合は監視を終了し、終了理由を記録に残す。
サーバーを止めると監視も止まり、サーバーを起動し直しても以前の監視を自動では再開しない。
ディスク使用量を制限するため、記録が16 MiBに達した場合は監視を終了する。

イベントは基板付近の変化を示すもので、人の在室を直接判定するものではない。
照会の間に終わる短い衝撃は見逃す場合があり、変化量のしきい値は観察の設定であって、校正した安全基準ではない。

## 演習一覧の参照

演習画面は、リポジトリの日英の README から、題名、前提となる演習、所要時間、目的の抜粋を読む。
学習順序には `tools/syllabus.py` を使う。
手順を開くか Make コマンドをコピーして、既存の手順で演習を実行する。
画面を開くだけでは、演習の実行や合格判定を行わない。

## ローカル接続と検証

HTTP の待ち受けは、既定では `127.0.0.1` とし、`--host` を指定した場合はその Tailscale IPv4 アドレスを使う。
指定できる値は `127.0.0.1` と `100.64.0.0/10` 内の IPv4 アドレスに限り、全インターフェース、LAN、ホスト名による指定は拒否する。
Tailscale の IP で待ち受ける場合は、ソケットの接続元も `127.0.0.1` または `100.64.0.0/10` 内に限定し、転送元を示す HTTP ヘッダーではこの検査を置き換えない。
サーバーは Host と Origin のヘッダーを検査し、処理の開始と記録の取り込みには、サーバーごとのトークンを要求する。
画面のファイルはリポジトリに含め、CDN のスクリプト、フォント、外部サービスは読み込まない。
USB の操作は既存のシェル照会と受信記録に限り、無線送信、ファームウェアの書き換え、任意コマンドの実行を受け付ける API は設けていない。

オフラインテストは、基板を接続せずに実行できる。
HTTP のテストでは USB の処理を制御可能なアダプタに置き換え、正常な処理の開始、処理の同時実行の拒否、不正な要求、別オリジンからの要求、記録のパスを検証する。

```bash
make flatsat-check
```
