# 用語集

*English: [glossary.md](glossary.md)*

この用語集は、このリポジトリの用語と表記の唯一の参照である。文書の側を用語集に寄せるのであって、その逆ではない。文書とこの用語集が食い違うとき、変わるのは文書の側である。下の「使わない表記」はすべて、2026-11-21 に日本語文書68件を走査して実際にリポジトリで見つかったものである。推測で挙げたゆれは無い。

## 目的

- 概念ごとに表記を1つに決め、両言語でそろえる。ある文書で出会った語が、ほかのすべての文書でも同じ形で読めるようにする。
- 日本語の正表記は、文書間で食い違う場合にリポジトリ自身の多数派で決める。争いのあった選択には、根拠の出現数を備考に残す。
- 略語の展開はここに置く。文書自体は略語を展開しないためである（下の略語のルールを参照）。
- 新しい用語は、文書へ広がる前に、まずここへ日本語の正表記と避ける表記とともに加える。

## 表記ルール

### カタカナ長音

原則として、英語の -er、-or、-ar で終わる外来語の末尾の長音は付けない。アダプタ（8件、アダプター 0件）、ハンドラ（21件、ハンドラー 0件）、エミュレータ（8件、エミュレーター 0件）、シミュレータ（4件、シミュレーター 0件）、ルータ（3件、ルーター 0件）、ユーザ（1件、ユーザー 0件）、マネージャ（3件、マネージャー 0件）、ドライバ（2件、ドライバー 0件）、パラメータ（2件、パラメーター 0件）、モニタ（2件、モニター 0件）、フィルタ（1件、フィルター 0件）、コントローラ（1件、コントローラー 0件）、メモリ（23件、メモリー 0件）。例外として長音を付ける語が3つある。リポジトリで例外なく、または多数派としてその形で使われているためである。サーバー（7件、サーバ 0件）、ポリシー（14件、ポリシ 0件）、ブラウザー（4件、ブラウザは CLAUDE.ja.md の1件のみ）。yomiyasu スキルは長音の揺れを原文のままにする流儀であり、この件の典拠にはならない。典拠はこの用語集であり、スキルの通常の好みとリポジトリの多数派が衝突した場合はリポジトリを正とし、例外を上に挙げた。

### 数字・単位・スペース

数字はすべて半角とする。走査では日本語文書に全角数字は1件も無かった。ラテン文字の単位は数字の後にスペースを入れる。2 MiB、1 Mbps、5 ms、5 V、986 Hz は、文書がすでに一貫して使っている形である。日本語の助数詞はスペースを入れない。30秒、3件、2機、4バイト。この助数詞のルールは、文書が現在破っている唯一のものである。EX-G03 と EX-G04 の文書には 30 秒 があり、README.ja.md には 30秒 があり、件、回、バイト、機はいずれも両方の書き方が現れる。したがって助数詞まわりは表記統一の最初の対象である。パーセント記号は数字に付ける（13%）。範囲は ～ でつなぐ（docs/flatsat.ja.md の 27.67～27.76 C）。日付は ISO 形式（2026-09-30）とする。

### 括弧・引用・記号

日本語の地の文では全角括弧 （） を使う。出現数は全角454件に対して半角246件であり、半角のほぼすべてはコード、識別子、関数呼び出し、パス、リンクであって、それらは半角のままにする。日本語の引用は 「」 を使う。二重引用符はリテラルの文字列と値のために残す。太字、コードスパン、リンクは周囲の文書の既存の慣行に従う。この用語集が決めるのは語の形であって、レイアウトではない。

### 略語と規格番号

略語は地の文で初出でも展開しない。これは不備ではなく、このリポジトリの確定した慣行である。CCSDS（日本語文書で31件）、PUS（89件）、CSP（43件）、SDLS（43件）は README.ja.md 以来ずっと無展開で使われており、展開の実例は docs/legal/export-control.ja.md の CubeSat Space Protocol 1件だけである。したがって展開は下の用語表に置き、必要な読み手はここへ来る。正確さが要る箇所では、規格名に文書番号を添える。CCSDS 355.0-B-2、CCSDS 132.0-B-3 の形である。ノード名 OBC、EPS、ADCS、COMM は両言語ともラテン大文字のままにし、Renode、Zephyr、CryptoLib のようなツール名とライブラリ名も同様とする。

### 演習 ID と PUS の表記

演習 ID は EX-Xnn の形とする。文字 EX、ハイフン、系列を表す英字1文字、0 埋め2桁の数字である。走査では754件が見つかり、ゆれは無かった。スペースを入れた形も、1桁の形も存在しない。ディレクトリ名は ID にハイフンつなぎのスラッグを続ける。EX-F02-key-extraction の形である。PUS のサービスは、サービスとサブタイプの組を PUS 17,1 と書き（カンマの後にスペースを入れない）、サービスだけなら PUS 8 と書く。PUS-C は、その規格バリアント自体を名指すときにだけ使う。ASSURANCE.ja.md が副ヘッダについてそうしているのが実例である。プロジェクト自身のプロトコルは ECSS PUS である。

### 文体

日本語文書は全体を通じて常体（だ・である）で書かれている。走査では68件すべてに常体の文末があり、敬体（です・ます）の文末は1件も無かった。新しい日本語の文は常体で書き、両者を混ぜない。英語文書は既存文書の平明な断定の文体に従う。両言語とも、コードの動作についての主張は、実行するか読むかして確かめた場合にだけ事実として書く。この点は README.md の証拠のルールが統治しており、用語集は何も付け加えない。

## 用語集の更新

用語は、2つ目の文書がその語を必要としたとき、または同じ概念を2つの文書が違う表記で書いているのが見つかったとき、その早い方でこの用語集に加える。争いのあった選択には根拠の出現数を記録し、あとから読む者が、測った多数派と推測とを見分けられるようにする。文書を用語集に寄せるときに変えるのは表記だけであり、用語の意味をそのついでに編集しない。このファイルと glossary.md は test_doc_parity.py の下で対をなすため、節、行、箇条書きを一方に加えたら、同じコミットでもう一方にも加える。
