# テストベッド文書

`hardware/` に設計資産を置く実機テストベッドの、仕様側の文書。テストベッド
ロードマップのフェーズ1（仕様凍結）は、基板が設計される前にここへ書き下す。

## 文書

| 文書 | 中身 |
| --- | --- |
| `hw-compat-table.md` | 全演習の実機仕分け: そのまま実機化、注入方法の変更が必要、Renode 専用。各々に必要なハードウェア機能 |
| `pinmap.md` | STM32H753 のピンマップについて、現行ファームウェアが既に固定している点と、まだ未決の点 |

## 凍結で確定すべきこと

- ピンマップ。ファームウェアが既に動いている Nucleo ボードに対して証明する。
- 電源・クロック・CAN の設定を、意図ではなく数値として固定する。
- `hw-compat-table.md` の演習仕分けをレビュー済みにする。
- 下記の合格閾値を、ハードウェアが存在する前に固定し、ベンチを事前に書か
  れた数値で判定できるようにする。

## 合格閾値（ドラフト）

値は未決だが、基準項目は決まっている。各々をフェーズ1で測定方法とともに
固定する。

| 基準 | 値 | 測定方法 |
| --- | --- | --- |
| 実配線幹線での PUS 往復の遅延 | 未決 | 未決 |
| 連続運転でのフレーム損失 | 未決 | 未決 |
| 介入なしの連続運転 | 未決 | 未決 |
| 演習後に全ノードを初期状態へ戻すまでの時間 | 未決 | 未決 |

## 状態

- フェーズ1は準備中。上表の文書はいずれもドラフトである。
- ここにあるものは、ハードウェアの存在や動作を主張するものではない。
