# EX-S05 — 誰が鍵を退役させたか

## 状況

EX-S04 は無認可の退役を止めたが、その `mitigation.md` は塞げなかった隙間で終わっていた：
**地上から見れば、盗まれた退役と運用者自身のローテーションは同じ事象**である。どちらも SPI 9 が
黙るだけ。association を*誰が*退役させたかの記録は COMM コンソールの一行（`by SPI 11` か
`by SPI 10` か）だけで、それは決して宇宙機を離れない。鍵が退役させられているのを見つけた運用者は、
見えるものからは、自分がやったのか敵がやったのかを言えない。

これは**検出**の半分である。EX-S04 の予防をやり直すのではない：**ここでは両ビルドとも認可を意図的に
OFF** にしてあり、連携局が本当に運用者の SA を退役させられる——それが要点で、帰属すべき退役が実際に
起きる必要があるからだ。違うのは宇宙機が**誰がやったかを報告するか**だけ。報告は EX-D01 の署名済み
ビーコンに乗るので、帰属は主張ではなく認証され、要求者 SPI は SDLS MAC が*証明*したものである。

## あなたの目的

運用者の SPI 9 を——連携局として、次に運用者として——退役させ、ビーコンを読め。**報告するビルドだけ
が、地上に「誰がやったか」を名指させる**ことを示せ。

```bash
make exercise EX=EX-S05-who-retired-the-key          # range 内のシェル
python3 exercises/EX-S05-who-retired-the-key/solve.py   # そのシェルのプロンプトで
```

`make exercise` は**range のネットワーク名前空間内**のシェルに入れ、ソルバはそこから実行する。
名前空間はループバックのみ（SAFE_USE.md）、呼び出しごとに新規作成されるため、別端末で起動したソルバは
`ConnectionRefusedError` になる。

連携局ではなく運用者として——*自分*として読めるべきローテーションを——退役させるには `--legitimate`：

```bash
make exercise EX=EX-S05-who-retired-the-key RUN='python3 exercises/EX-S05-who-retired-the-key/solve.py --legitimate'
```

## 何が起きたか

```text
ビルド        STOP_SA の送信者       SPI 9 後   ビーコン:退役SA   ビーコン:退役させたSPI
vulnerable    連携局   (SPI 11)         暗転        （なし）           （なし）
vulnerable    運用者   (SPI 10)         暗転        （なし）           （なし）
hardened      連携局   (SPI 11)         暗転        SPI 9              SPI 11
hardened      運用者   (SPI 10)         暗転        SPI 9              SPI 10
```

**vulnerable の2行は同じ観測である。** 連携局による盗難も運用者によるローテーションも、SPI 9 を
暗転させ、ビーコンは空のまま。地上からは区別がつかない——これが EX-S04 の盲点そのもの：退役は起き、
コンソールは誰かを記録し、運用者はそれを決して見ない。

**hardened の行はそれらを分離し、分離する値は要求者 SPI である。** `retired by SPI 11` は運用者では
なかった連携局、`retired by SPI 10` は運用者自身の第二の鍵。運用者はビーコンを読み、たった今どちらが
起きたかを知る——コンソールが最初から知っていて、言えなかった唯一のことを。

**4行目は、対策が単なる警報ではなく*実際の退役者*を名指さねばならなかった理由である。** すべての退役
を怪しいと騒ぐ報告は、運用者が意図的に鍵をローテーションした最初の一回で無用になる。*SPI 10——あなた*
と言える帰属こそが、これを煙探知機ではなく制御にする。

## 結論として

**効く制御は、効いていると聞こえねばならない。** これは EX-G04 と EX-U03 の教訓が鍵管理層に来たもの。
EX-S04 の認可は確かに誤った相手を拒否する——だが、誰も読まないコンソールにしか届かない拒否や退役は、
運用者が行動できない決定である。帰属こそが「SPI 9 が黙った」と「SPI 11 が SPI 9 を退役させた」の差だ。

**帰属は、証明に束ねられた名であって、ラベルではない。** ビーコンの要求者 SPI は、ディレクティブの
MAC を検証した SA——攻撃者が持たねばならなかった所持——であって、埋めた欄ではない。そしてそれは
EX-D01 の署名の下で運ばれるので、下りの鍵を持たない攻撃者は報告自体を偽造も抑圧もできない。未認証の
帰属は EX-D02 の検出器の再来——証言を被告が書く証人——になってしまう。

`mitigation.md` は、そのビーコンフィールド、なぜ長さが機能テストなのか、なぜ自分で署名せず EX-D01 に
寄りかかるのか、そして今なお*できない*こと——**最後の**退役しか運べず、SA 管理イベントの連続が 1 件に
潰れる、EX-S03 の refused-SPI と同じ限界——を述べる。
