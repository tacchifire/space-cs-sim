# EX-D01 — 誰も送っていない拒否

## 状況

ここまでの攻撃はすべて宇宙機を狙っていた。**この演習は運用者を狙う。**

EX-G04 は報告経路を作った演習である。その所見は「指令を拒否し、誰も見ていないコンソールにだけ
そう書く制御は、地上が使えない制御である」——地上から見れば、拒否と不達は同じ観測になる。
そこで宇宙機は PUS 1,2 を送ることを覚えた。Request ID をそのまま、理由を添えて。

EX-S02 はそのあと全テレコマンドに MAC を載せ、宇宙機は認証できる要求にしか作用しなくなった。
**両方向に手が入った。鍵が入ったのは片方だけである。**

報告を認証するものは、何も無い。

## 目的

**運用者に「あなたの送った指令は拒否された」と信じ込ませる。**

あなたはクロスリンクにいる。EX-X01、EX-S01、EX-S02 が置いていった場所である。鍵は無い——
そして**今回は要らない**。

```bash
make exercise EX=EX-D01-a-refusal-nobody-sent          # range の中のシェルに入る
python3 exercises/EX-D01-a-refusal-nobody-sent/solve.py   # そのシェルのプロンプトで
```

`make exercise` は **range のネットワーク名前空間の中**のシェルに入る。ソルバはそこから走らせる。
名前空間にはループバックしか無く（SAFE_USE.md）、起動ごとに新しく作られるので、
別の端末で起動したソルバは `ConnectionRefusedError` を受け取る。

シェルではなく1コマンドだけ走らせるなら:

```bash
make exercise EX=EX-D01-a-refusal-nobody-sent RUN='python3 exercises/EX-D01-a-refusal-nobody-sent/solve.py'
```

## 何が起きたか

```
運用者のコンソール: refused APID 0x0A9 seq 0: not authorised (to station 0x0042)
COMM のコンソール:  downlink 22 octets from node 13
OBC のコンソール:   （何も無い）
```

**OBC は指令を見ておらず、拒否しておらず、報告を送っていない。** 運用者の手元には、正しい APID、
正しいシーケンス番号、自局の ID、そして辻褄の合う理由を持った拒否がある。

経路は関数1つである。COMM の下り送信タスクは CSP ポート 10 を bind し、**どの送信元からの接続も
受け入れ**、到着したものを TM トランスファフレームに包む。**どのノードから来たかをログに書きながら、
検査はしない。** クロスリンク上の僚機が、被害機自身の COMM にテレメトリを手渡し、
被害機がそれを運用者の下りリンクに送信する。

## 結論すべきこと

**認証には向きがあり、片方は忘れやすい。** EX-S02 の文書は「報告はトレーラを持たない」と書き、
未完了として名指ししていた。**これが、運用者の椅子から見た「未完了」である。**

**偽造された拒否が実際に何をするかを考えること。** 何のスイッチも切らない。
運用者に「いま試していることは通らない」と、**運用者自身のコンソールの語彙で**、
**本当に送った指令について**告げる。運用者は止める。あるいは、正しく動いている権限表の調査に
パスを1回使う。EX-G04 は地上が**信頼する**チャネルを与えた。地上が信頼するチャネルは、攻撃する価値がある。

**そして、より悪い系がある。** これが使えるなら、**本物の拒否を、もっともらしい偽造で埋めて
見えなくする**こともできるし、成功した指令を拒否されたように見せることもできる。
宇宙機が実際に送った報告は、送っていない報告と区別が付かない。

対策と、そのうち宇宙機の側に無い部分は `mitigation.ja.md` にある。
