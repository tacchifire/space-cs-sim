# EX-D01 — 対策

## 修正は2箇所にあり、宇宙機はそのうち1箇所でしかない

`CUBERANGE_OBC_SIGN_REPORTS=1` が、EX-S02 がテレコマンドに載せたのと同じトレーラを報告に載せる:

```
primary(6) | PUS TM secondary(7) | time(4) | application data | SEQ(4) | MAC(16)
```

**そして地上局がそれを要求しなければならない。** `GroundStation(..., require_signed_tm=key)`。
トレーラが**在れば**検証し、**無ければ**受理する局は、**単に付けない**攻撃者に破られる——
巧妙な攻撃ではなく、そして「任意のセキュリティ」がたいてい行き着く形である。
フラグを ON にして局が要求しない設定で実測: **偽造は今も通る。**

この分割は見た目以上に重要である。**COMM は修正ではないし、修正になれない。**
対策版で COMM が何をするかを見ること:

```
COMM のコンソール:  downlink 22 octets from node 13
運用者のコンソール: （信じたものは無し。1 件を未認証として拒否）
```

**偽造フレームは今もリンクを下っていく。** COMM が PUS ポートに来たものを包むのは、
無線がそうするものだからである。そして本物の報告と偽造を見分けられるのは、
**鍵を持っていて、答えを気にしている側**である。制御は受信側にある。

## 安い部分対策と、それが残すもの

COMM は自機の OBC からの下り送信だけを受けることもできる——トポロジ検査、EX-X01 の形である:

```c
if (csp_conn_src(conn) != OBC_ADDR) { /* うちの送るものではない */ }
```

これはこの攻撃を止め、フレームあたりの費用はゼロで、やる価値がある。
しかし**下りリンクそのものに送信できる者は止めない**——実際のリンクでは、
アンテナと宇宙機の SCID を持つ誰もがそれである。トレーラは両方を止める。
どちらも安く、十分なのは片方だけであり、**どちらがどちらかを文書が言う**——
安い方が完成に見えてしまわないように。

## 解決しないこと

- **鍵を持った僚機。** 報告の署名も同じ1本の鍵を使う。侵害された宇宙機は他機の報告も偽造できる。
  `keys.py` が、書き下された1本の鍵が教材レンジにとって誠実な形である理由を長く述べている——
  ミッションにとって弁護できる形だとは言っていない。
- **抑止。** 認証は偽造を**検出可能**にする。**届かなかった本物の報告**については何もしない。
  それは EX-G04 の問題であり、今もそこにある——地上は、抑止された拒否と受理された指令を
  区別できない。署名された報告は宇宙機が**言ったこと**を証明する。**言わなかったこと**は証明できない。
- **トラフィック解析とタイミング。** 報告を偽造できない攻撃者も、報告がいつ出るかは見られる。
- **カウンタ。** 報告のシーケンス番号は宇宙機ごとに単調だが、**地上は現在それの欠落を見ていない**。
  欠落こそが「報告が抑止された」信号であり——上で唯一、認証が助けになり得た点であり——
  この range はそれを読んでいない。ほのめかすのではなく名指ししてある。

## ここから持ち帰る価値のあること

5つの演習が1つの文に収束し、これは**誰も見ない向き**である。

EX-X01：防御は資産にではなく経路に付いている。
EX-G04：報告できない制御は、地上が使えない制御である。
EX-S01：システムで最も強い制御も、やはり経路に付いている。
EX-S02：ならば、本当に気にしている対象に束縛せよ。
EX-D01：**そして、それを両方向でやったかを確かめよ。**

どれも「前の修正が覆わなかったものは何か」と問うことで見つかった。
EX-G04 が作った報告チャネルは修正だった。**地上がそれを信頼することを覚えた瞬間に攻撃面になり**、
反対方向を狙った2巡の暗号を経ても、そのままだった。
