# EX-L02 — 落ちたのか、取られたのか

## 状況

EX-D02 は検出器を作り、その文書自身が「まだ出会っていないもの」を名指しした:

> **実リンクでの誤検知。** 損失のあるチャネルはフレームを落とし、実際の運用者は攻撃者のいない
> 欠落を見る。この range にはビット誤りが無いので、**ここでの欠落はすべて誰かの判断である。**

チャネルはフレームを落とせるようになった。`frame_loss` が下りフレームを独立に、固定シードで落とす。
**無線モデルではないし、そう装ってもいない**——変調も符号化もバースト構造も無い。
EX-D02 が問えなかった問いを問うのに足りる、それだけである。

1割を落とすリンクで指令を20通:

```text
攻撃者が一人もいない       gaps [(11,13,1), (16,18,1)]              欠落 2
報告が1通取られてもいる     gaps [(3,5,1), (11,13,1), (16,18,1)]     欠落 3
```

**検出器はどちらの実行でも正しい。** ただ、問いに答えるのをやめただけである。

## 目的

**報告が3通欠けている。そのうちどれが「誰かに取られた」のかを言え。**

```bash
make exercise EX=EX-L02-lost-or-taken          # range の中のシェルに入る
python3 exercises/EX-L02-lost-or-taken/solve.py   # そのシェルのプロンプトで
```text

`make exercise` は **range のネットワーク名前空間の中**のシェルに入る。ソルバはそこから走らせる。
名前空間にはループバックしか無く（SAFE_USE.md）、起動ごとに新しく作られるので、
別の端末で起動したソルバは `ConnectionRefusedError` を受け取る。

シェルではなく1コマンドだけ走らせるなら:

```bash
make exercise EX=EX-L02-lost-or-taken RUN='python3 exercises/EX-L02-lost-or-taken/solve.py'
```

## 何が起きたか

```text
リンクが 2 落とし、攻撃者が 1 取った
運用者に見える欠落: [(3,5,1), (11,13,1), (16,18,1)]   （3 件）
訊いた: [4, 12, 17]
宇宙機が再送した: [12, 17]
戻ってこなかった: [4]
```

3件すべてについて訊く。2件は戻る——**それはリンクだった**。1件は、何度訊いても戻らない。
それを取っているものが、また取るからである。**戻ってこないものが攻撃である。**

## 結論すべきこと

**欠落は問いであり、その問いを発せない検出器は、数字を出しているだけである。**
EX-D02 のカウンタは運用者に「何かが欠けている」と教えた。清浄なリンクではそれが答えの全部だった。
実リンクでは**答えの始まり**である。それを終わらせるのは、宇宙機へ戻る経路と、答えられる宇宙機である。

**ここでは再送がセキュリティ制御である。そして誰もそこには分類しない。**
報告バッファは普通、信頼性の機能として扱われる——サイズ、溢れ、カウンタのラップ。
しかしこの range で**攻撃と天候を区別できる唯一のもの**がそれである。

**そして脆弱版が何をするかに注目すること。何も無いより悪い。** ストアが無いと、
3件すべてについて訊いて、3件すべてに沈黙が返る:

```text
宇宙機が再送した: []
戻ってこなかった: [4, 12, 17]
```

同じ手順に従った運用者は、いま「**3通が取られた**」と結論する。
手順は安全側に倒れたのではない。**確信側に倒れた。**
否定的な結果が「確認できなかった」と区別が付かない検出手順は、**所見を製造する手順**である。

バッファ・その代価・訊くことが効かなくなる場所は `mitigation.ja.md` にある。
