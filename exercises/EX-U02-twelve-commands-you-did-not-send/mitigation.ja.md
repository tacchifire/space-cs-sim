# EX-U02 — カウンタと、それに言えないこと

## 対策ビルドがすること

`CUBERANGE_OBC_TC_COUNTERS=1` は OBC に16ビットのカウンタを2つ、ビーコンに4オクテットを足す。

```c
static uint16_t tc_accepted;   /* この宇宙機が「聞いた」テレコマンドすべて */
static uint16_t tc_rejected;   /* そのうち拒否した数 */
```

`tc_accepted` は **ECSS の受理が決まる場所**——パケットの形と長さフィールドが通り、ハンドラが走る前
——で増える。`tc_rejected` は各拒否点で増える。**拒否された指令は両方で数えられる。** 一瞬おかしく
読めるが意図的であり、`send_acceptance_success` が既に持っていた意味論と同じで、理由も同じである。
拒否された指令は**聞かれた**のであり、問いは「届いたか」だからである。

報告は既存のハウスキーピング・ビーコン（PUS 3,25）に相乗りする。したがってコストは
**ビーコン1本あたり4オクテットと、新規パケット0**。この射場で断然最安の検出器である。

地上局は**2つの報告の差分**を読み、値そのものは読まない。16ビットは折り返す。絶対値で読む検出器は
65536指令に1回必ず間違う。宇宙機の再起動はカウンタを0に戻し、大きな負のステップとして現れる。
これは正直な挙動である——再起動後に「誰かが65000指令送った」と報告する局は、正直ではない。

## コスト

ビーコンあたり4オクテットの電波時間、`uint16_t` 2つ分の RAM、テレコマンド経路上のインクリメント2回。
測定にかかるほどのものは無い。

**本当のコストは地上側にあり、小さくない。局はパスをまたいでベースラインを保持しなければならない。**
カウンタは前回の読みに対してしか読めないので、記録を失った運用者は次のパスで新しい基準を作るまで
検出器を失う——そしてその窓の中の侵入は、以前とまったく同じに不可視である。
`GroundStation` は**指令の前、信号捕捉時に**ベースラインを取る。これは算術を正確にする条件でもある:
最初の指令が数えられた後にベースラインを取ると、原点が1指令ぶんずれ、`commands_heard` は真値16に
対して15を返す。**実測である。数はそこから来た。**

## それでもできないこと

- **攻撃者と同僚を区別すること。** `unexplained_commands` が言うのは「**あなたは一人ではない**」で
  あって、「攻撃を受けている」ではない。正当な2つ目の地上局は1行目とまったく同じ値を出す。
  EX-G03 の主題が場所を変えて再来している。自分のコンステレーションを知らない運用者は、
  同僚を調査することになる。
- **どの指令かを言うこと。** これは数であってログではない。「16聞いて8送った」は、送っていない
  テレコマンド8個が受理されたことを言うが、それが何を要求したかは言わない。実機なら直近 N 件の
  テレコマンド request id を保持する——EX-L02 が作った蓄積を上りリンクに向けたもの——が、
  この射場には無い。
- **単一の数として読まれても耐えること。** これは**差引**である。1行目の侵入は、そこから引かれる
  遮断を**自ら引き起こした**。だから12個のプローブが +8 と読める。`commands_heard` と
  `commands_sent` を横に出しているのはそのためで、差引は自分の項を隠す。+8 を小さな侵入と読んだ
  運用者は、3分の1だけ過小評価している。
- **COMM が拒否したものを数えること。** カウンタは OBC にあり、**リンク層認証の後ろ**である。
  偽造フレーム、リプレイ、MAC 不一致——どれもこのカウンタに届かない。したがって**鍵を持たない**
  攻撃者は、上りリンクを叩いている間じゅうこの検出器に映らない。本演習が扱うのとは逆の死角であり、
  そしてそちらの攻撃者のほうが**ありふれている**。カウンタは両ノードに要る。ここでは片方にしか無い。
- **未実装サービスを拒否すること。** この OBC は PUS 3,1 に printk 1行で答え、受理として数える。
  本来の ECSS 受理は未実装サービスを**拒否**する。そうすれば侵入者の12個は `tc_rejected` に入り、
  検出器は**より強く**なる——「12件拒否」は侵入者についての文だが、「12件受理」はまず引き算が要る。

## 2つ目の Security Association

1行目の締め出しは**演出ではない**。二度読む価値がある。

COMM はアンチリプレイカウンタを**1つ**しか持たない。この射場の Security Association が**1つ**だから
である。ファームウェアは EX-S01 以来コメントでそう述べ、修正は未実装だと述べてきた。
**その代償を初めて測ったのが本演習である。** 侵入者の12個のプローブがカウンタを進め、運用者の次の
4フレームはその後ろに届き、COMM は**リンク層で**拒否する——だから OBC はその指令を見ず、受理応答も
拒否報告も返らない。地上から見れば、**あなたの鍵を使う侵入者は EX-U01 の遮断された上りリンクと
区別がつかない**。符号を見るまでは。

CCSDS 355.0-B-2 はアンチリプレイ状態を SA に置き、SA は仮想チャネルに属す。送信者が2つなら SA も
カウンタも2つになり、衝突しない。これを実装すれば締め出しは消える。**つまり侵入者はさらに静かになり、
症状はゼロになり、カウンタだけが唯一の証拠になる。本ファイルの対策は、より重要になるのであって、
不要になるのではない。**

## ここから持ち帰るべきもの

EX-U01: 誰も何も作らなかった向きを確かめよ。
EX-U02: **そして、作ったもののどれかが「自分の通信」と「他人の通信」を区別できるかを確かめよ。**

この射場のあらゆる制御は**フレームについての問い**に答える。MAC は送信者が鍵を持つかを問う。
権限表は送信元 ID が名簿にあるかを問う。アンチリプレイカウンタは番号が新しいかを問う。
鍵を持つ侵入者は3つとも満たす。**どれ一つとして「これは誰の通信か」を問うていない**からである。
そしてこの射場でその問いを最初に発した制御は、電波時間4オクテットの2オクテットのカウンタだった。
