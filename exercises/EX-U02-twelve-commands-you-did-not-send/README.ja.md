# EX-U02 — あなたが送っていない12個の指令

## 状況

EX-U01 は、自分に無いものを名指して終わった。

> **上りリンクのカウンタ。** 存在しない。宇宙機には「あなたから 40 個の指令を聞いた」と言う手段が
> 無く、地上には「41 のはずだ」と気づく手段が無い。

本演習はそのカウンタである。そして作る理由は、EX-U01 が挙げた理由ではない。

**鍵が他人の手に渡っている。** どうやってかは本演習の主題ではない——EX-F01 は OBC 上のコード実行で
終わるし、運用センターのノート PC 上の鍵はそれより短い話である。重要なのは、この射場のあらゆる制御が
それに対して何をするかで、答えは**何もしない、正しく**、である。SDLS の MAC は検証される。
テレコマンド認証も検証される。アンチリプレイ番号も新しい。**暗号は鍵と、鍵を持っている人間とを
区別できない。** EX-S01、EX-S02、EX-D01 で作ったどれ一つとして、元々そうする気は無かった。

侵入者は、**あなたが宇宙機の上空にいない間に**送信する。

## 目的

1回のパスで指令を送り、しばらく圏外になり、もう一度指令を送る。**留守の間に何が起きたか**を言え。

```bash
make exercise EX=EX-U02-twelve-commands-you-did-not-send          # 射場内部のシェル
python3 exercises/EX-U02-twelve-commands-you-did-not-send/solve.py   # そのプロンプトで
```

`make exercise` は**射場のネットワーク名前空間の内側**にシェルを開く。ソルバはそこから実行しなければ
ならない。名前空間にはループバックしか無く（SAFE_USE.md）、呼び出しごとに新しく作られるので、
別の端末で起動したソルバは `ConnectionRefusedError` になる。

シェルではなく単一コマンドを実行するには:

```bash
make exercise EX=EX-U02-twelve-commands-you-did-not-send RUN='python3 exercises/EX-U02-twelve-commands-you-did-not-send/solve.py --no-intruder'
```

## 何が起きたか

```text
カウンタ   侵入者   2回目のパス   応答    宇宙機が聞いた   送った   説明のつかない数   拒否
あり       あり     -             4/8        16            8          +8             0
あり       なし     -             8/8         8            8           0             0
あり       なし     遮断          4/8         4            8          -4             0
なし       あり     -             4/8         -            8         判定不能         -
なし       なし     -             8/8         -            8         判定不能         -
```

**1行目と3行目は同じ症状である。** 4個応答があり、その後のパスでは何も返らない。一方は鍵を握った
侵入者、もう一方は上りリンクが食われている状態。必要な対応は正反対——鍵の更新とインシデント対応か、
アンテナとリンクバジェットか——であり、**両者を分けるものはこの射場にただ一つ、ある数の符号だけ**である。

**+12 ではなく +8。** 12個のプローブが上がった。この数は**差引**である。侵入者自身の送信がリンクに
一つしかないアンチリプレイカウンタを進め、あなたの2回目のパスをその**後ろ**に置いた。だから COMM は
あなたの4個をリンク層で拒否し、OBC は一度も聞いていない。**16聞いて8送った**。+8 を「侵入者の指令が
8個」と読む運用者は、数を取り違えている。

**拒否が0であり、それが発見の半分である。** プローブは一つも権限表に届いていない。この OBC が実装
していないサービス/サブタイプの組み合わせであり、宇宙機の外から誰も読めないコンソールに1行出て終わる。
**侵入者はまだ何もしていない。ここに何があるかを調べている。** そう言っているのは「多く聞いた・一つも
拒否していない」という**数の対**である。

**カウンタの欠落は何も語らない。** 1行目で15、2行目で4。どちらも圏外の間にビーコンが動いていた分で
あり、誰かの攻撃ではなく**あなた自身のパススケジュール**である。EX-L02 と EX-L03 が作った検出器は、
仕様どおりに動いている。

## 結論

**ここにあるすべての制御は「このフレームは正当か」に答える。「このフレームは自分のものか」には
誰も答えない。** MAC は鍵の所持を証明する。権限表は送信元 ID が名簿にあることを証明する。
アンチリプレイカウンタは番号が新しいことを証明する。鍵を持つ侵入者は3つとも満たす。
3つとも**フレーム**についての問いだからであり、**フレームの集合**についての問いは、誰かが数えるまで
この射場に存在しなかった。

**証人は機上に置かなければならない。** 運用者が持つ他のすべては**その場の**下りリンクを読む。
その場の読みは、**居合わせた分しか**見えない。侵入者は誰もいない空へ送信し、そのプローブが引き出した
受理応答は誰にも受信されなかった。それでも**数は次のパスに残っていた**。カウンタは状態であり、
ストリームは状態ではないからである。

**注意は証拠を追う**——EX-U01 の一文であり、これが2番目ではなく16番目の演習である理由でもある。
上りリンクは観測を生まなかった、だから何も作られなかった、だから**あなたの鍵を持つ侵入者はそこへ行く**。

`mitigation.md` はカウンタ本体と、区別できないもの、そしてこの射場にまだ無い**2つ目の
Security Association** について。
