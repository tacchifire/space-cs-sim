# EX-X01 — 対策

## 修正

`CUBERANGE_OBC_CROSSLINK_ORIGIN=1`。条件は1つ:

```c
static bool origin_permits_claim(uint16_t source_id, uint16_t via)
{
	if (source_id != GROUND_PRIMARY_ID && source_id != GROUND_BACKUP_ID) {
		return true;
	}
	return via == COMM_ADDR;
}
```

`via` は `csp_conn_src(conn)`——パケットが**実際に到着した** CSP アドレスであり、ルータが接続から
埋めた値である。送信者が PUS ヘッダに書いた何かではない。

地上局を名乗るパケットは、この宇宙機自身の COMM から来ていなければならない。
僚機は話しかけてよい。僚機が地上であってはならない。

実測。同じ攻撃、同じ瞬間、2つのビルドを並べて:

```
CUBERANGE_OBC_CROSSLINK_ORIGIN=0   OBC: PUS 8 executed - COMM rail OFF
                                   EPS: COMM rail OFF (commanded)

CUBERANGE_OBC_CROSSLINK_ORIGIN=1   OBC: REJECTED a packet claiming source 66 that arrived
                                        from node 13
                                   OBC: PUS 1,2 acceptance failure reported to source 66 (code 4)
```

## なぜこの形か

自明な修正は「送信者を認証せよ」であり、この range にはそれができない。SDLS は未実装であり
——`ASSURANCE.md` がそう書いており、真になるまで書き続ける——ラボ実装をしたところで主張が
真になるわけでもない。

そこでここの制御は別のものを検査する。**パケットがどこから入ったか**——攻撃者が選べない——を、
**誰が送ったか**——攻撃者が書き込む——の代わりに見る。これはトポロジ検査である。認証より弱く、
今日使える。この取引は隠すより書いておく。

**しないこと**も記す。衛星1が衛星0に話しかけること自体は止めない。僚機同士には用事があり、
演習冒頭の中継がまさにその用事である。拒むのは特定の主張1つだけ——この宇宙機の外から到着した
パケットが地上であるという主張である。

## 解決しないこと

- **自機の COMM が侵害された場合。** `via` は COMM_ADDR になり、検査は通る。この制御は COMM を
  信じる。どこかで何かを信じなければならないからであり、信頼境界を動かすことは信頼境界を無くす
  ことではない。ここで動かした先は、アップリンクをデフレームするために既に信じるほかなかった
  ノードである。
- **宇宙リンクに送信できる者。** この制御はアップリンクについて何も言わない。そこは EX-L01 の
  領分であり、EX-L01 の対策文書も自らの答え——シーケンスカウンタ——が認証ではないと同じくらい
  はっきり書いている。
- **僚機が僚機として指令してくる場合。** 正当な隣機が何を要求してよいかは、ここでは何も制限して
  いない。権限表は地上局 id を鍵にしており、宇宙機に対する同等物は無い。作るなら、その id を
  ヘッダのフィールドより良い何かに束縛しない限り、この演習の誤りを繰り返すことになる。
- **内部ノードへの直接到達。** クロスリンクは今も衛星0の EPS と ADCS へ経路を持つ。
  `verify_ex_x01.py` は EPS が**両方のビルドで**拒否することを実測している——
  `REJECTED unauthenticated rail command from node 13`——が、それは EPS 自身の制御が働いたので
  あって、この制御ではない。パケットの到着を止めたものは何も無い。EX-A01 のトルク制限も同様に、
  発信元ではなくコマンドに対する検査である。どちらも同じ理由で新しい経路を生き延びる——
  要求者についての主張ではなく、要求そのものの性質を検査しているからである。
- **2本目のクロスリンク。** 検査は COMM_ADDR という1つのアドレスと比較する。無線を2つ持つ
  宇宙機は両方を要り、信頼する接続点の一覧とは、間違え得るものの一覧である。

## ここから持ち帰る価値のあること

経路上に制御が2つあり、片方が効いた。

EPS はトークンを要求する——攻撃者が**持って**いなければならないもの。その作者が考えもしなかった
経路を生き延びた。所持は、どうやって来たかに依存しないからである。

OBC は発信元 id を要求した——攻撃者が**書く**もの。生き延びなかった。2つ目の経路ができた初日に、
生き延びなかった。

入口を増やしたとき壊れる制御は、主張を鍵にしているものである。自分の制御のどちらがどちらかを
見極める作業は、この演習のやり方で発見するより安い。

## 直せない場合の検知

対策版の拒否は攻撃者には返らない。`send_acceptance_failure` はこの宇宙機自身の COMM に接続する
ので、PUS 1,2 は**宇宙リンクを下って本物の地上局に届く**——自分が送っていないコマンドが自分の名前で
拒否されたことを、その局が知る。

これは一見以上に良い信号である。発行した記録の無い request id について拒否を受け取った地上局は、
自分の宇宙機から「誰かがあなたの身分を使っている」と告げられている。この range の他のどれも、
それを生まない。

## 静かに失敗した配線について

クロスリンク接続点は自分自身の CSP アドレスを持つ（`8i + 6`、4つのノード役割と並ぶ）。
これは飾りではない。libcsp の split horizon は `csp_io.c` に3回現れ、毎回同じことを訊く:

```c
if (csp_iflist_is_within_subnet(iface->addr, routed_from)) continue;
```

**送出側**インタフェースのアドレスを、**受信側**インタフェースのサブネットと比較している。
ルータの2つのインタフェースをどちらもノード自身のアドレスで登録すると——この実装の最初の版が
そうしたように——これはあらゆる netmask で真になる。`csp_iflist.c:21` は netmask からマスクを
組み立て、netmask 0 はマスク 0 を組み立て、その下ではあらゆるアドレスがあらゆるアドレスと等しい。
そしてルータは**何も転送しない**。エラーもログ行もカウンタも無い。パケットは fdcan2 に到着し、
そこで止まる。

見つけ方は、フレームを注入して EPS が何も言わないのを見ることだった。それは**フレームが届かな
かったときに EPS が言うこと**でもある——EX-G04 と同じ観測が、1層下で起きていた。
