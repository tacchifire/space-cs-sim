# EX-S02 — 対策

## 修正

`CUBERANGE_OBC_REQUIRE_PUS_AUTH=1`。OBC は何かをディスパッチする前にテレコマンド自身の MAC を
検証し、トレーラをその場で剥がす。下のパーサが見るのは署名されたオクテットそのものになる:

```c
if (!pus_auth_ok(packet->data, &plen)) {
        printk("OBC: REJECTED an unauthenticated telecommand from node %u\n", csp_conn_src(conn));
        csp_buffer_free(packet);
        continue;
}
handle_space_packet(packet->data, plen, csp_conn_src(conn));
```

**下のどのハンドラもこれを知らない。** それは意図的である——全ハンドラが呼ぶことを覚えていなければ
ならない制御は、どれか1つが忘れる。そして忘れたその1つが、面白い方である。

3つの部品が効いており、どれも荷重を負っている:

- **MAC が発信元 id を覆う。** それが EX-X01 が偽装するフィールドであり、
  いまはパケットがどこから来ても覆われている。
- **シーケンス番号が認証範囲の内側にある。** 進めれば MAC が壊れるので、
  カウンタを上げて録音を再生することができない——EX-L01 の攻撃の、1層上。
- **長さフィールドが、MAC 計算の前にトレーラを覆うよう書き換えられる。**
  攻撃者がトレーラを切り落とすために変えなければならない数が、それ自身認証されている。

再送カウンタは**発信元 id ごと**であり、リンクに1本ではない。2つの地上局は2人の送信者であり、
その間で1本のカウンタを共有するのは EX-G03 の3度目である。
ここでは限界として書き下すのではなく**実装した**。この range は同じ間違いを既に2回しており、
3回目は教材にならないからである。

## 代価

- **全テレコマンドに20オクテット。** 実測: 同じ PUS 17,1 のペイロードが 11 から 31 になる。
  毎秒数百ビットで測るリンクではこれは無料ではなく、**実際のミッションが MAC をフレーム層に置く
  理由**でもある——CCSDS がそうしたのがそれであり、EX-S01 はまさにその判断の帰結を見せている。
- **検証する全ノードが鍵を要る。** いま OBC が持っている。テレコマンドを受ける payload 計算機が
  あればそれも要り、代理で転送する何かも要る。**信頼しなければならないものの集合が増えた。**
- **ノンス。** GCM はノンス再利用に対して破滅的である——平文だけでなく**認証副鍵が漏れる**——
  そしてこのプロファイルはノンスを送らず APID・発信元 id・シーケンスから導出する。
  1つの鍵の中でそれが重複するのは、ある発信元がシーケンス番号を再利用したときだけで、
  それは再送検査が拒否する事象そのものである。よって2つの性質は1つの性質である。
  `pus_auth.py` にも、ゴールデンファイルにも、ここにも書いてあるのは、
  **将来カウンタを緩める変更が、再送検査だけでなく暗号そのものを無言で壊す**からである。

## 解決しないこと

- **鍵を持った僚機。** コンステレーションの共有秘密は全員が持っており、侵害された宇宙機も
  メンバーである。`keys.py` が教材レンジにとって書き下された1本の鍵が誠実な形である理由を
  長く述べているが、生き残る文は「**固定の共有秘密は、証明するものではなく持っているもの**」である。
- **認可。** EX-G02 は無傷であり、**これがこのファイルで最も重要な行である。**
  認証は「誰か」に答える。「何を」には一度も答えていない。
  認証された局が持つべきでないものを求めるのが EX-G02 であり、これら全部のあとにも残っている。
- **テレメトリ。** 逆向きの報告はトレーラを持たない。EX-G04 は「地上が聞けない拒否は使えない」と
  確立した。**地上が認証できない拒否は、攻撃者が偽造できる拒否**であり、
  誰からでも「あなたの指令は拒否された」と言われ得る運用者は、試すのをやめさせられる運用者である。
  未実装。名指ししてある。
- **鍵の配布・更新・失効。** 何も無い。ヘッダファイルの定数1本である。

## ここから持ち帰る価値のあること

4つの演習が同じ1文に着き、EX-S02 はそれを**裏返す**ものである。

EX-X01：防御は資産にではなく経路に付いている。
EX-G04：報告できない制御は、地上が使えない制御である。
EX-S01：システムで最も強い制御も、やはり経路に付いている。
EX-S02：**ならば、本当に気にしている対象に束縛せよ。**

宇宙機が作用する対象は要求である。最初から認証すべきはそれだった。
普通そうしない理由は、**フレーム層の方が安く、標準が既に書かれているから**である。
それは本物の工学的トレードであり、この演習はそれを否定しない——
そのトレードが何を買い、何を払うかを、**線の上のオクテット数で**見せる。
