# EX-L03 — 起きなかったパス

## 状況

EX-L02 は、自分の修正が届かない場合を名指しして終わった:

> **完全な遮断。** 何も届かなければ欠落は生じず、訊く対象も無い。
> **静かなパスは欠落ではなく**、それに気づくにはスケジュールが要る。

カウンタの欠落は、その間に挟まる報告が2通要る。**全部を遮断すれば、運用者のコンソールには
空の欠落一覧が出る**——それは完璧なパスが見せるものとまったく同じである。

## 目的

攻撃者がパス全体を遮断する。**それを言え。**

```bash
make exercise EX=EX-L03-the-pass-that-never-happened          # range の中のシェルに入る
python3 exercises/EX-L03-the-pass-that-never-happened/solve.py   # そのシェルのプロンプトで
```

`make exercise` は **range のネットワーク名前空間の中**のシェルに入る。ソルバはそこから走らせる。
名前空間にはループバックしか無く（SAFE_USE.md）、起動ごとに新しく作られるので、
別の端末で起動したソルバは `ConnectionRefusedError` を受け取る。

シェルではなく1コマンドだけ走らせるなら:

```bash
make exercise EX=EX-L03-the-pass-that-never-happened RUN='python3 exercises/EX-L03-the-pass-that-never-happened/solve.py'
```

## 何が起きたか

4通り。そして4行目が噛みしめるべきものである:

```text
ビーコン  攻撃      聞こえた  カウンタ欠落  スケジュールの判定
あり      なし        36        []          ok
あり      全遮断       0        []          silent
なし      全遮断       0        []          silent
なし      なし         0        []          silent      <- 誰も何もしていない
```

**カウンタ欠落は全行で空である。** 完全な遮断は欠落を作らない。完璧なパスも作らない。
**言うことが無い宇宙機**も作らない。

スケジュールは最初の2行を分ける。**最後の2行は分けない。そこが所見である。**

## 結論すべきこと

**スケジュールには「期待する対象」が要る。** ビーコンの無いビルドでは、宇宙機は訊かれたときしか
喋らない——つまり**沈黙が正常状態**であり、窓は毎回発火し、この手順に従った運用者は
静かなパスのたびに調査を開くことになる。従うのをやめるまで。

地上側の制御と宇宙機側の振る舞いは、**2つの対策ではなく1つ**である。
EX-D02 と同じ文を、反対側から言っている——あちらでは入力が偽造可能で検出器は**開いて**失敗した。
ここでは入力が**存在せず**、閉じて失敗する。どちらも同じ誤りであり、
**検出器を、それが何の上に立つかを問わずに建てたこと**である。

**そして、効いている版が買うものの少なさに注目すること。** 静かな窓が教えるのは
「期待していたときに何も聞こえなかった」ことだけである。宇宙機が遮断されたのか、落ちていたのか、
別方向を向いていたのか、予測が外れていたのかは教えない。
「**何も分からない**」を「**聞くべきときに聞こえなかったと分かる**」に変える——
感じるより小さな一歩であり、そして**誰かが見に行く**一歩である。

ビーコン・その代価・その下にある時計の問題は `mitigation.ja.md` にある。
