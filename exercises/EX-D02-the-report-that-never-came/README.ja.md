# EX-D02 — 来なかった報告

## 状況

EX-D01 は、自分の修正が覆わないものを名指しして終わった:

> 認証は偽造を**検出可能**にする。**届かなかった本物の報告**については何もしない。
> それは EX-G04 の問題であり、今もそこにある——地上は、抑止された拒否と受理された指令を
> 区別できない。署名された報告は宇宙機が**言ったこと**を証明する。**言わなかったこと**は証明できない。

宇宙機は報告に署名する。運用者はそれを検証する。そして**1通を取り去った攻撃者は、
運用者に「短くなった一覧」と「何かが足りないと思う理由が何も無い状態」を残す。**

## 目的

この演習は他のすべてと違う。**何かを壊せとは言われていない。**

指令が3通送られる。報告が何通か返る。**運用者のコンソールから見えるものだけで、
宇宙機が3通すべてに答えたかどうかを判断せよ。**

```bash
make exercise EX=EX-D02-the-report-that-never-came          # range の中のシェルに入る
python3 exercises/EX-D02-the-report-that-never-came/solve.py --drop &
```

`make exercise` は **range のネットワーク名前空間の中**のシェルに入る。ソルバはそこから走らせる。
名前空間にはループバックしか無く（SAFE_USE.md）、起動ごとに新しく作られるので、
別の端末で起動したソルバは `ConnectionRefusedError` を受け取る。

シェルではなく1コマンドだけ走らせるなら:

```bash
make exercise EX=EX-D02-the-report-that-never-came RUN='python3 exercises/EX-D02-the-report-that-never-came/solve.py --drop'
```

ソルバは運用者と宇宙機の間に座り、報告を1通取る。**その位置は演習のために作った作り話ではない。**
侵害された地上系フロントエンド——スケジューラ、復調出力のハンドラ、アンテナとコンソールの間の何か——が
座る位置であり、EX-G01 が攻撃するのと同じサプライチェーン上の位置である。
妨害電波はこれより精度が低く、侵害された地上系はこれより多くのことができる。

## 何が起きたか

同じ攻撃、2つの設定:

```
署名を要求する局          gaps [(0, 2, 1)]   欠落として認識: 1
要求しない局 + --replace  gaps []            欠落として認識: 0
```

1行目を可能にしているのは、宇宙機が全報告に入れているカウンタである。
2行目は**同じ攻撃者が同じ場所で**、局の署名検査を切った状態——報告を取り、
**欠けたはずのカウンタ値を持つ1通を置いていく**。穴は閉じる。

## 結論すべきこと

**欠落検査と署名検査は、2つの対策ではない。1つである。**

**入力を攻撃者が制御している検出器は、何も検出しない。** 報告カウンタが良い信号であるのは、
**攻撃者がそれを書けない間だけ**である。それを買うのがトレーラであり、
だからこの演習の修正は「カウンタも見る」ではなく「**認証済みのテレメトリについてカウンタを見る**」である。

一般形で述べる価値がある。これはテレメトリの話ではないからである。
**認証されていない証拠の上に建てた検出は、装飾である。**
攻撃者が書けるログ行、攻撃者が設定できるカウンタ、攻撃者が送れるハートビート——
どれも制御に見え、そして**何も見えていない場所を見に行かせる**。

**そして残るもの。必ず残る。** 認証されたカウンタは「報告が欠けている」と教える。
**中身が何だったかは教えない。** 欠落を見た運用者が知るのは「宇宙機が何かを言い、自分はそれを
聞かなかった」ことだけである——知らないよりは良く、知っていることとは違う。

対策・その代価・これでも直らないものは `mitigation.ja.md` にある。
