# EX-D02 — 対策

## 修正

地上局が報告カウンタを読む。**既に認証したテレメトリについて**:

```python
GroundStation(link, require_signed_tm=key)      # 両方か、どちらも持つ価値が無いか
...
station.counter_gaps      # [(last, current, missing), ...]
station.reports_missing   # 運用者が「受け取らなかった」と分かる通数
```

`_advance` は4行で、うち1行はラップの話である。16ビットのカウンタは巻き戻る。
**1日1回「65534通が欠落」と報告する局は、2日目には切られている。**
後退や極端に大きな跳びはラップや順序入れ替わりとして扱う——この局は**欠落の検出**を主張しており、
履歴の再構成は主張していない。

**2つの検査の順序が、対策そのものである。** 認証してから数える。逆順は、攻撃者が書いたオクテットを数える。

## 代価

- **宇宙機側はゼロ。** カウンタは最初からあった——PUS は全 TM 副ヘッダにメッセージカウンタを置き、
  OBC は最初からそれを進めていた。EX-D02 の修正は**完全に地上局の中**にある。
  ここでは珍しい形で、注目に値する——**証拠は存在しており、誰も読んでいなかった。**
- **実リンクでの誤検知。** 損失のあるチャネルはフレームを落とし、実際の運用者は
  攻撃者のいない欠落を見る。ミッションは欠落を**警報ではなく確認の合図**として扱うだろう。
  この range にはビット誤りが無い（SAFE_USE.md がチャネルの未模擬項目を列挙している）ので、
  **ここでの欠落はすべて誰かの判断である。**

## 解決しないこと

- **欠けた報告の中身。** 欠落は「宇宙機が喋り、あなたは聞かなかった」と言う。
  それが拒否だったか、成功だったか、ハウスキーピングだったかは言わない。
  電源指令の最中に欠落を見た運用者は**訊くべきだと分かる**。答えは分からない。
- **全部の抑止。** 下りリンクを丸ごと取る攻撃者は、**欠落を1つも作らない**——
  比較する後続の報告が無いからである。完全な遮断は「言うことが無い宇宙機」と区別が付かない。
  EX-G04 の所見がもう一度であり、ミッションがパススケジュールを持ち、
  **静かなパスに気づく**理由である。
- **最初の報告。** その前に数えるものが無い。接続したばかりの局は、
  自分が最初から見ているのかを判断できない。
- **侵害された宇宙機。** カウンタは宇宙機が持つ鍵で署名される。
  乗っ取られた宇宙機は、欠落の無いカウンタを含め、好きなものに署名する。

## ここから持ち帰る価値のあること

6つの演習、そしてこれは**攻撃についてではない**唯一のものである。

EX-X01：防御は資産にではなく経路に付いている。
EX-G04：報告できない制御は、地上が使えない制御である。
EX-S01：システムで最も強い制御も、やはり経路に付いている。
EX-S02：ならば、本当に気にしている対象に束縛せよ。
EX-D01：そして、それを両方向でやったかを確かめよ。
EX-D02：**そして、自分の検出が何の上に立っているかを確かめよ。**

カウンタはこの range の初日から全報告に入っていた。**報告が認証された日に役に立つようになり、
それ以前ではなかった。** そしてその間ずっと、それは制御に見えながら、
**何も見えていない場所を見に行かせるもの**だった。
