# EX-U03 — 無線自身の申告と、1つの数に言えないこと

## 対策ビルドがすること

`CUBERANGE_COMM_LINK_STATS=1` は COMM に16ビットのカウンタを2つ足す。

```c
static uint16_t link_frames_rx;        /* そもそも到着したフレーム */
static uint16_t link_frames_refused;   /* この無線が捨てたフレーム */
```

`rx` は `on_tc_frame` の先頭、どの検査よりも前で増える。`refused` は**フレームを拒否して return
するすべての地点**で増える: SDLS の MAC 不一致、SDLS アンチリプレイ拒否、平文アンチリプレイ拒否
（VC 別・リンク別の両経路）、仮想チャネルが読めない場合、FECF/長さ不正。**6箇所**である。
後から7箇所目を足して数え忘れれば、カウンタは黙って**過少申告**する。だからインクリメントは
先頭の1箇所にまとめず、**`return` の隣**に置いてある。

スレッドが2秒ごとに CSP ポート12で OBC へ組を送り、OBC がハウスキーピング・ビーコンに載せる。
**無線は自前のテレメトリ経路を持たない。** 実機なら送受信機に APID を与えるだろう。同時に実機なら
計算機がサブシステムのハウスキーピングを集約もする。**新しい配線が要らないのは後者だった。**
その選択の代償は下の「できないこと」にある。

OBC はリンク統計を **COMM の CSP アドレスからのみ**受け付ける。どこからでも受ける計算機は、
内部バス上の何者にでも「無線が何を見たか」という宇宙機自身の申告を書かせることになる。
これは EX-B01 の前提を、電源ではなく**テレメトリ**に向けたものである。

ビーコンは、**無線が実際に報告してきて初めて**4オクテット伸びる。それ以前にゼロで埋めることはしない。
**地上では長さが機能判定である**——4オクテットは何も数えない宇宙機、8はテレコマンドを数える宇宙機、
12は無線が拒否数も数える宇宙機。12に埋めてしまえば、**何も知らない宇宙機について「拒否は0件」と
地上局に告げる**ことになる。それは黙っているより悪い唯一の答えである。

## コスト

ビーコンあたり4オクテット、`uint16_t` 2つ、2KB スタックのスレッド1本、そしてほぼ空いているバス上を
2秒ごとに流れる4オクテットの CSP パケット。

**注意すべきはスレッドで、この射場には傷跡がある。** `K_THREAD_DEFINE` に `K_TICKS_FOREVER` を
渡したスレッドは、**誰かが起動するまで走らない**。本ビルドの最初の版は20件の拒否を正しく数え、
**1件も報告しなかった**——脆弱側と見分けのつかない、静かな半端機能である。**実測で見つけた。
コードを読んで気づけるものではなかった。**

## それでもできないこと

- **敵と悪天候を区別すること。** これが最大のものである。壊れたフレームと偽造フレームが、ここでは
  **1つの数**になっている。SDLS ビルドでは FECF 検査が `sdls_verify` の内側にあるので、
  何かが数える時点で**拒否理由は失われている**——そして理由こそが区別のすべてである。
  FECF 不正は雑音、FECF 正常で MAC 不一致は**誰か**である。実機なら理由別の小さなヒストグラム
  （4〜5個のカウンタ）を8オクテット追加で持つ。この射場は1つしか持たない。本当に雑音の多いリンクで
  これを読んだ運用者は、**電離層を調査する**ことになる。
- **誰か、どこからかを言うこと。** これは数である。周波数も、到来時刻も、ドップラーも、方向も無い。
  実機は拒否の集中を指向スケジュールと突き合わせて位置を出す。ここには突き合わせる相手が無い。
- **起きている最中に報告すること。** 数はビーコンに乗る。ビーコンが届くのは運用者が可視にいるとき
  だけである。不可視中の攻撃は**次のパスで見え、それ以前には見えない**。EX-U02 のカウンタと同じ
  性質であり、今回に限ればそれは**長所**である——カウンタは**残る証人**だからである。
- **無線自身が乗っ取られた場合に耐えること。** 以上すべては、**無線自身の振る舞いについての無線自身の
  申告**である。乗っ取られた COMM は好きなことを報告し、機上の誰もそれを照合しない。
  OBC のテレコマンドカウンタが COMM と独立しているのは価値がある——COMM が「全部拒否した」と言う一方で
  `unexplained_commands` が非ゼロなら、それは運用者が動ける**矛盾**である——が、
  **その比較を代わりにやってくれるものはこの射場に無い。**
- **フレームにすらならなかったものを数えること。** キャリア妨害、飽和した受信機、同期しなかったビット。
  デフレーマはこれら全部の下流なので、**フレームが成立しない攻撃は「静かなリンク」として記録される**。
  症状は `rx` がゼロになることだけであり、静かなリンクが地上からどう見えるかは EX-U01 の主題である。

## ここから持ち帰るべきもの

EX-U01: 誰も何も作らなかった向きを確かめよ。
EX-U02: そして、作ったもののどれかが「自分の通信」と「他人の通信」を区別できるかを確かめよ。
EX-U03: **そして、既に正しく働いている制御が「働いた」と言えるかを確かめよ。**

この宇宙機の MAC は偽造フレーム10発を拒否した。アンチリプレイカウンタは録音10発を拒否した。
どちらも正しく、どちらも速く、そしてどちらも結果を——**この射場の歴史上、一度も宇宙機を出たことのない
コンソール**に書いた。**報告できない防御は「半分の防御」ではない。「完全な防御と、検出ゼロ」である。**
そしてその違いは、**通ってしまった攻撃の前の週に何を知っていたか**にしか現れない。
