# EX-U03 — 誰も数えなかった20件の拒否

## 状況

EX-U02 は、自分の検出器の**裏側の死角**を名指して終わった。

> **COMM が拒否したものを数えること。** カウンタは OBC にあり、**リンク層認証の後ろ**である。
> 偽造フレーム、リプレイ、MAC 不一致——どれもこのカウンタに届かない。したがって**鍵を持たない**
> 攻撃者は、上りリンクを叩いている間じゅうこの検出器に映らない。本演習が扱うのとは逆の死角であり、
> そしてそちらの攻撃者のほうが**ありふれている**。

本演習の攻撃者は**鍵を持たない**。リプレイ10発と偽造10発が上がる。

**あらゆる制御が、正しく、完全に、それらを拒否する。** 偽造フレームで SDLS の MAC は検証されない。
録音はアンチリプレイカウンタが拒否する。ペイロードは一つも搭載計算機に届かず、機上では何も変わらず、
一瞬たりとも危険は無い。**これが「防御が完璧に働いた」姿である。**

偽造に鍵は要らない。ここははっきりさせておく価値がある——フレームの FECF は **CRC であって MAC では
ない**。誰でもオクテットを書き換えて計算し直せる。**それがチェックサムの用途であり、そして用途では
ないことである。** だから下に MAC がある。

## 目的

あなたが見ている前で、宇宙機が20フレーム分攻撃される。**そう言え。**

```bash
make exercise EX=EX-U03-twenty-refusals-nobody-counted          # 射場内部のシェル
python3 exercises/EX-U03-twenty-refusals-nobody-counted/solve.py   # そのプロンプトで
```

`make exercise` は**射場のネットワーク名前空間の内側**にシェルを開く。ソルバはそこから実行しなければ
ならない。名前空間にはループバックしか無く（SAFE_USE.md）、呼び出しごとに新しく作られるので、
別の端末で起動したソルバは `ConnectionRefusedError` になる。

シェルではなく単一コマンドを実行するには:

```bash
make exercise EX=EX-U03-twenty-refusals-nobody-counted RUN='python3 exercises/EX-U03-twenty-refusals-nobody-counted/solve.py --no-attacker'
```

## 何が起きたか

```text
無線が報告   攻撃者   投げた数   応答    欠落   説明のつかない数   受信   拒否
あり         あり       20       4/4     無し         0            23     20
あり         なし        0       4/4     無し         0             3      0
なし         あり       20       4/4     無し         0             -   判定不能
なし         なし        0       4/4     無し         0             -   判定不能
```

**3行目と4行目は、運用者に見えるものが何一つ違わない。** 「防御の成功は、攻撃が無かったことと
区別がつかない」とは、断言ではなく**実測すると**こういう意味である。機上のコンソールは20回拒否を
印字し、その**どの一部も宇宙機を出ていない**。

**`説明のつかない数` の列を見よ。** 攻撃者がいる行も含めて全行が **0** である。これは1つ前の演習で
**まさに攻撃者を検出するために**作った EX-U02 の検出器である。それは**計算機**が聞いた数を数え、
無線は計算機の**前**にある。**この攻撃を止めた制御こそが、攻撃を見るために作った検出器から
その攻撃を隠したものである。**

**20ではなく「23分の20」。** このリンクのフレームレートが本来いくつかを知る地上局は無い。
だから拒否の**数**だけでは文にならない。**比**が文になる。

## 結論

**静かに成功する制御は、あなたより攻撃者に多くを教える。** 相手は「MAC は本物だ」「リプレイ窓は
狭い」と学ぶ。**無料で**である。あなたの側に「試された」という記録が何も残らないからだ。
あなたは何も学ばない——標的であることも、いつかも、どこからかも、他と突き合わせる価値があることも。
次に来るときは**通るもの**を持ってきて、それがあなたが相手について聞く**最初の報せ**になる。

**検出は層に属し、攻撃を止める層は、たいていそれを見られる層ではない。** EX-U02 のカウンタが OBC に
あるのは、そこがテレコマンドを数える場所だからである。この攻撃は**1ノード手前で死ぬ**。
どちらのカウンタも間違ってはいない。**それぞれが、もう一方の見る攻撃者に対してちょうど盲である。**
運用者はどちらの種類が来るかを事前に知れないので、宇宙機には**両方**が要る。

**そしてこれは EX-G04 の、1層下での再演である。** *報告できない制御は、地上が使えない制御である。*
EX-G04 はそれを拒否されたテレコマンドについて確立し、射場は PUS 1,2 で直した。
**PUS の下、無線の中で起きている拒否——数の上ではそちらが大多数である——について、同じ問いを
誰も立てなかった。**

`mitigation.md` はカウンタ本体、比に言えること・言えないこと、そして「攻撃されている」と
「雑音が多い」がここではまだ1つの数である理由について。
