# EX-L01 — 読めないテレコマンドをリプレイする

*English: [README.md](README.md)*

## 状況

EX-B01 は EPS が認証されない電源指令を拒むところで終わった。
その対策文書は、この制御がリプレイ可能だと認めていた。
それを取り立てにいく。

今回は内部バス上にいない。
**宇宙リンク**上にいる。
正しい空を向いた受信機を持つ者の位置である。
上がっていくテレコマンドと下りてくるテレメトリが聞こえ、こちらからも送信できる。

電源トークンは持っていない。
必要ない。

## 目的

観測したバイトだけを使って衛星を沈黙させる。
成功条件は `EPS: COMM rail OFF (commanded)` が2度目に現れることである。
運用者は関与しない。

## 動いているもの

```
地上局 --> [ チャネル ] --> COMM.usart2 --CSP/CAN--> OBC --> EPS
               ^
          ここにいる。全フレームが見え、送信もできる
```

EPS は EX-B01 の**対策版**である。
バスフレームの偽造はここでは通らない。
運用者の正規経路は PUS 8,1 の機能1で、OBC がそれを受けて EPS に認証済みの電源指令を送る。

衛星は自力で復帰する。
EPS は COMM のレールが落ちた30秒後に復電する。
実機がこの種のインターロックを積むのは、悪い指令1つが、もっと良い指令を送れる唯一の経路を恒久的に断てないようにするためである。
この演習が観測可能なのも、それのおかげである。

## 実行

```bash
make firmware-exl01
python3 exercises/EX-L01-tc-replay/solve.py     # 模範解答
make verify EX=EX-L01-tc-replay
```

## ヒント

<details><summary>ヒント1 — 何を捕まえるか</summary>

運用者が目に見える効果のあることをしている間、アップリンクを見張る。
`LinkChannel` は全フレームを `uplink_frames` に記録する。
欲しいのは、レールを落としたフレームである。
</details>

<details><summary>ヒント2 — 何を送るか</summary>

組み立てるものは何も無い。
`LinkChannel.replay()` が捕まえたフレームをバイトそのままで送信する。

符号化し直してはいけない。
やり直すと、本物の防御が検査しているフィールドを偶然直してしまうかもしれず、そうなると2つのうちどちらを試したのか分からなくなる。
</details>

<details><summary>ヒント3 — 時刻</summary>

リプレイに意味を持たせるには、衛星が生きている必要がある。
`EPS: COMM rail ON (FDIR restore)` を待ってから送信する。
</details>

## 何を結論すべきか

面白いのは、攻撃者が何を持っていなかったかである。
トークンも、鍵も、パーサも無い。
そのフレームのどのフィールドが何を意味するのかも知らない。

指令を**瞬間**に結び付けない認証は、要求ではなくメッセージを認証している。
そして録音は、いつまでも完全に有効なメッセージである。

誰が EPS の認証を破ったのかにも注目してほしい。
攻撃者の代わりに OBC が破った。
EX-B01 の対策は送信者が秘密を知っているかを検査するもので、送信者は知っていた。
衛星は自分自身の正当な振る舞いを忠実に再演していた。

Willbold らは実在の衛星ファームウェアでまさにこの形を報告している（*Space Odyssey*, IEEE S&P 2023）。
暗号はあっても同等の認可保証が無いこと、そして固定された資格情報の所持が権限として扱われるテレコマンド経路である。

## そして直す

[mitigation.ja.md](mitigation.ja.md) を見てほしい。
検証は3方向すべてを assert する。

| テスト | 何を assert するか |
| --- | --- |
| `test_replay_succeeds_against_the_vulnerable_comm` | 捕まえたバイトの再送で無線がまた落ちる |
| `test_replay_is_rejected_by_the_hardened_comm` | 同じバイトが拒否される |
| `test_the_hardened_comm_still_accepts_new_commands` | 運用者の次の指令は今も通る |
