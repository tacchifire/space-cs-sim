# EX-S03 — Security Association 表と、誰も交換しなかった鍵

## 対策ビルドがすること

**このペアは、両方の半分が表を持っている。表は差分ではない。**

```c
struct cr_sdls_sa {
        uint16_t spi;
        const uint8_t *key;
        bool operational;          /* 状態フィールド。この射場に必要な1ビットに縮めたもの */
};

static const struct cr_sdls_sa sa_table[] = {
        { CR_SDLS_SPI,         cr_sdls_key,         /* EX-S03 の対策側で無効化 */ },
        { CR_SDLS_SPI_ROTATED, cr_sdls_key_rotated, true },
};
```

`CUBERANGE_COMM_SA_DEACTIVATION=1` は退役 association を非運用に印付ける。**その1ビットが
ペアの差分のすべてである。** 新しい鍵だけを積んだビルドは、古い association を**拒否する**宇宙機では
なく、それを**話せない**宇宙機である。単一フレームからは同じに見えるが**同じ制御ではない**。
そしてペアゲートは、どちらでも喜んで「対策」と呼んだだろう。

状態の検査は **MAC の前であり、後ではない。** 無効化された SA の鍵は何の検証にも使ってはならない。
MAC を先に検査すれば、**退役した鍵がなおフレームの適格性を決める**ことになり、それを持つ攻撃者は
「無効化された association」と「存在しない association」を**応答時間で区別できる。**

拒否は**理由**を持つようになった。4種、別々である。**運用者を4つの別の場所へ送る**からである。

```
not a well-formed authenticated frame      デフレーマかレイアウト
no such security association               他の宇宙機宛のフレーム、または当て推量
that security association is DEACTIVATED   あなたが退役させた鍵を誰かが使っている
the MAC does not verify                    鍵を持たない誰か
```

最後に拒否したフレームの SPI は、EX-U03 が作った計数と一緒に OBC へ行き、ビーコンに乗る。
ビーコンは**14オクテット**になった。**不正形式のフレームについては送らない**——
レイアウト検査に落ちたフレームの SPI 欄は**たまたまそこにあったオクテット**であり、それを報告すれば
**誰も使っていない association を地上が調査する**ことになる。

## 頼んでいないのに付いてきたもの

**アンチリプレイが Security Association ごとになった。** CCSDS 355.0-B-2 がそこに置いているもので
あり、COMM のソースが **EX-S01 以来「未実装」と述べてきた**ものである。
EX-U02 が単一カウンタの代償を測った: 運用者の鍵を握った侵入者がそれを進め、運用者の次のフレームは
その後ろに届き、COMM は**正当な局**をリンク層で拒否し、受理も拒否報告も地上に届かなかった。

**これが何を直さないかを注意して見よ。** **1つの** SA を共有する2つの送信者は**依然として衝突する**。
そのカウンタを共有しているからであり、それは**まさに EX-U02** である——その侵入者は
**運用者が使っていた association の鍵**を盗んだのだから。**盗まれた鍵は、窃取者に2つ目の SA を
与えない。** 修正は本物であり、そしてそれの修正ではない。

## それでもできないこと

- **もう一方の鍵を交換すること。** この射場には鍵が**2つ**あり、交換したのは**1つ**である。
  ミッション層のテレコマンド認証（EX-S02）はいまも元の定数で検証する。それを握る攻撃者は
  依然としてテレコマンドに署名できる——**ただ、届けるためのフレームを無線の先へ通せないだけ**である。
  それは多層防御が意図通り働いている姿であり、**同時に、流通したままの未交換の鍵**である。
  2層のうち1層しか覆わない交換は**半分の交換**であり、**本演習はそれを成功として報告する。**
- **運用中に SA を無効化すること。** 表は `const` でコンパイル時固定であり、この交換は
  **ソフトウェア更新として飛ばされた**。実機はテレコマンドで SA を無効化する——そして
  **運用者自身の association を無効化できるテレコマンドは、正当な MAC 付きのサービス妨害である。**
  それを作れば次の演習は勝手に書ける: 誰が鍵を退役させる権限を持つのか、無効化が有効化より先に
  届いたらどうなるのか、運用可能な SA が1つも無くなった宇宙機は何をするのか。**いずれも未実装である。**
- **拒否の連続がどの association に属したかを言うこと。** 値は1つ、最後のものだけ。
  2つの SPI にまたがる拒否は2番目しか報告されない。実機なら SA 別の小さなヒストグラムを持つ。
  **「退役させた鍵」と「鍵を全く持たない」を区別するには足り**、インシデントの時系列には足りない。
- **無効化と有効期限切れを区別すること。** CryptoLib は SA 状態を4つ持つ（unkeyed・keyed・
  operational・expired）。この違いは、この射場がやらない鍵管理にとって重要である。
  **ここでは1ビットであり、1ビットとして明記してある。**
- **交換が起きたことそのものを証明すること。** ネガティブ試験が証明するのは「**いま**古い鍵が
  拒否される」ことである。新 SA が運用可能になってから旧 SA が無効化されるまでの**窓**については
  何も言わない。実際の交換ではその窓は**数時間から数日**あり、**そこが面白いことが起きる場所**である。

## ここから持ち帰るべきもの

EX-U01: 誰も何も作らなかった向きを確かめよ。
EX-U02: そして、作ったもののどれかが「自分の通信」と「他人の通信」を区別できるかを確かめよ。
EX-U03: そして、既に正しく働いている制御が「働いた」と言えるかを確かめよ。
EX-S03: **そして、切ったつもりの制御が切れていることを、「通してくれ」と頼んで確かめよ。**

これ以前のすべての演習は、**欠けていた制御**か**報告できなかった制御**についてである。
本演習は、**実施され、検証され、そして未完了だった**制御についてである——
そしてそれが検証を通ったのは、**検証が、変更のうち音を立てる側の半分を試験したから**である。
**有効化は自ら名乗る。無効化は、誰も送信しない方向の沈黙である。**
