# EX-S03 — 退役させた鍵

## 状況

EX-U02 の侵入者は**あなたの鍵**を持っていた。そして機上のあらゆる暗号制御が彼らを通した——
**暗号は鍵と、鍵を持っている人間とを区別できない**からである。その答えは**鍵を変えること**であり、
本演習は「鍵を変える」が実際には何で構成されているかについてである。

CCSDS 355.0-B-2 は鍵を、暗号モード・アンチリプレイ番号・**状態**とともに
**Security Association（SA）**に入れる。**鍵を退役させるとは、その SA を無効化することである。**
したがって鍵交換には二つの半分がある——新しい SA を有効化し、古い SA を無効化する——そして
**症状があるのは前半だけである。** 前半だけをやれば、運用者は新しい鍵材料で指令し、すべての指令は
通り、すべての報告は返り、そして**窃取者はいまも扉を開ける鍵を握っている。**

この射場は今まで Security Association を**1つ**しか持たなかった。COMM のソースは SPI を検査する
コメントでそう述べていた。**いまは2つある。**

## 目的

新しい鍵での指令は通っている。**古い鍵がもう通らないことを示せ。**

```bash
make exercise EX=EX-S03-the-key-you-retired          # 射場内部のシェル
python3 exercises/EX-S03-the-key-you-retired/solve.py   # そのプロンプトで
```

`make exercise` は**射場のネットワーク名前空間の内側**にシェルを開く。ソルバはそこから実行しなければ
ならない。名前空間にはループバックしか無く（SAFE_USE.md）、呼び出しごとに新しく作られるので、
別の端末で起動したソルバは `ConnectionRefusedError` になる。

シェルではなく単一コマンドを実行するには:

```bash
make exercise EX=EX-S03-the-key-you-retired RUN='python3 exercises/EX-S03-the-key-you-retired/solve.py --no-retired-test'
```

## 何が起きたか

```text
退役SA       試験   SPI 10 応答   SPI 9 応答   受信   拒否   最後に拒否したSPI
無効化       あり        4            0          8      4          9
無効化       なし        4            -          4      0          0
有効のまま   あり        4            4          8      0          0
有効のまま   なし        4            -          4      0          0
```

**2行目と4行目は同じ観測である。** 一方は鍵を退役させた宇宙機、もう一方はさせなかった宇宙機であり、
**古い SA で一度も送信しない運用者に、両者を区別する手段は無い。** どちらも壊れていない。
どちらのコンソールにも欠落は無い。**完了した鍵交換と、放棄された鍵交換の違いは、
探しに行くまで不可視である**——そして**たった今退役させた鍵で送信してみる**のは自明な行動ではない。
だからこそ鍵交換は**試験されないまま**になる。

**1行目が証明であり、証明にしているのは SPI である。** 「4フレーム拒否」だけなら、
リンク不良でも、フレーム破損でも、当て推量でも成り立つ。`最後に拒否したSPI = 9` は
**あなたが退役させた association が追い返された**と言っている。コンソールは理由を言葉で言う——
*that security association is DEACTIVATED*。これは *the MAC does not verify* とは**別の文**であり、
運用者を**別の場所**へ送る。

**3行目が失敗であり、それが「どう見えないか」を見よ。** 8指令受理、拒否0、テレメトリに何も無く、
コンソールにも何も無い。**退役させた鍵は通り、宇宙機はそれで完全に満足している。**

## 結論

**試験していない制御は、仮定している制御である。** これが演習の全部である。鍵交換は実施され、
新しい鍵は検証され、すべて動いた——そして**その検証は、症状のある側の半分を試験した。**
重要なのは**拒否**の側であり、**拒否は「拒否してくれ」と頼むことでしか観測できない。**

**無効化が生む証拠は、ネガティブ試験だけである。** 有効化は自ら名乗る——指令が通り始める。
**無効化は、誰も送信しない方向の沈黙である。** 「古い鍵を拒否する」と「まだ一度も訊かれていない」を
区別する方法は、**訊くこと**以外に無い。

**そして拒否が証拠になるには理由が要る。** EX-U03 は無線が「**何件**捨てたか」を言う能力を作った。
本演習はそれに「**どの association か**」を言わせる必要があった。
「あなたが退役させた鍵を誰かが使っている」と「誰かが鍵を全く持たずに来ている」は
**対応の異なる別のインシデント**であり、**数はそのどちらも運べない。**

`mitigation.md` は SA 表、それが連れてきたアンチリプレイの修正、**交換されなかった鍵**、そして
**自分の association を無効化できるテレコマンド**について。
