# EX-S06 — スナップショットだった場所のログと、保持しない履歴

## 対策ビルドがすること

このペアは両半分とも**認可 OFF**・**報告 ON**——連携局の退役は着弾し、COMM は誰がどの SA を退役させたかを
記録する、EX-S05 が残したままだ。唯一のフラグ `CUBERANGE_COMM_SA_MGMT_HISTORY` は、記録したイベントの
うち何件が宇宙機を離れるかだけを決める。

```c
/* handle_sa_directive、退役ごとに */
sa_log_append(target_spi, sa_table[requester].spi);   /* MAC が証明した要求者 SPI */

/* send_link_stats */
int n     = CUBERANGE_COMM_SA_MGMT_HISTORY ? sa_log_count : 1;              /* 何件送るか */
int first = CUBERANGE_COMM_SA_MGMT_HISTORY ? 0 : (sa_log_count - 1);        /* どこから */
```

COMM は**両ビルドとも**直近 `SA_LOG_MAX`（＝4）件のイベントを到着順にリングで保持し、フラグは送信深度で
ある。OFF は `sa_log[count-1]` だけを送る——EX-S05 が送った単一スナップショットとバイト単位で同一。ON は
リング全体を古い順に送る。OBC は告げられたものをハウスキーピングビーコンに載せ、地上が読む。

**長さが機能テストである、末端まで。** COMM のリンク統計パケットは退役なしで 6 オクテット、`k` 件記録で
`6 + 4·k`。ビーコンは 14 と `14 + 4·k`。退役ゼロの宇宙機は短形式を送るので、空ログは*何も起きていない*を
意味し、*報告が壊れている*ではない——EX-S05 が `SPI 0 が SPI 0 を退役` の詰め物を拒んだのと、EX-U03 が
ゼロのリンクカウントの詰め物を拒んだのと、同じ理由である。

**帰属は認証されるが、このフラグによってではない。** ビーコンは EX-D01 の制御
（`CUBERANGE_OBC_SIGN_REPORTS`）で署名され地上局が要求する。これはそれに乗る。意図的だ——報告の認証は
この range が既に持つ制御であり、ここで再実装すれば1つのフラグに2つの考えが入る。EX-S06 が足すのは*内容*
——最後の1件ではなく系列——だけ。各項の要求者 SPI はディレクティブの MAC を検証した SA であってヘッダ欄
ではないので、「SPI 11 が退役させた」は所持についての言明である。

## これが解決しないこと

**リングより長い履歴。** バッファは直近 `SA_LOG_MAX` 件を drop-oldest で保持する。4件を超える SA 管理
イベントの系列は最も古いものを失う——EX-S03 の `link_refused_spi` と EX-S05 のスナップショットが抱えた
単一値限界が、消えたのではなく1サイズ大きくなった。この range には SA が3つしかないので4は十分な余裕だ
が、より忙しい SA 管理チャネルなら溢れる。実ミッションの監査ログも同じくストレージに束縛される。正直な
言明は、有界ログは*より良いスナップショット*であって、無限の記録ではない、である。

**SA による帰属であって、当事者ではない。** 各項はディレクティブの MAC を検証した SA を名指すのであって、
その鍵を保持する人や局ではない。運用者の SPI 10 の鍵を盗んだ侵入者（EX-U02 の前提）がそれで SPI 9 を
退役させれば「SPI 10 が退役」と記録される——運用者自身の鍵、暗号上は運用者と区別がつかない。SA による
帰属は、その下の鍵管理とちょうど同じ強さであり、この range は鍵管理を行わない。EX-S05 が抱えたこの限界を
EX-S06 も持ち上げない。

**予防。** このビルドは盗難を*報告*する。止めはしない——認可は意図的に off。実配備では EX-S04 の認可と
EX-S06 のログが一緒に走る：前者が連携局の退役を拒否し、後者が、実際に起きた SA 管理イベント——運用者自身
の退役や、迂回・誤設定された認可が通したもの——を運用者が監査できる順序で記録する。各々が1つの考えであり、
ペアゲートがそれを証明するので、2演習に分けてある。

## ここから持ち帰るべきこと

EX-S05：誰がどの SA を退役させたかを地上が読める場所に置け。
EX-S06：**そして系列を保て。最新の状態だけを報告する制御は2件目のイベントで無力化される——しかも2件目は
あなた自身の日常的な行為であり得るので、無力化は何も起きていないように見える。**

この range が作った報告する制御はどれも*状態*を報告していた：最後の拒否の SPI、最後の退役の帰属、現在の
カウンタ。状態はスナップショットであり、スナップショットは上書きされる。2つの事が2つのビーコンの間に
起きた瞬間、最初は消える——そして正当な行為に上書きされるよう仕向けた攻撃者は、最新だけを保持する検出器に
は不可視だ。ログはそれを生き延びる最小のもの：到着順のイベントなので、上書きされたものがまだ読める。
